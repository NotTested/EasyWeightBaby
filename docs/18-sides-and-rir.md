# C5 좌우 수행과 마지막 RIR

운동 상세의 실제 수행 행마다 수행 측(`unspecified`, `both`, `alternating_both`, `left`, `right`), 세트 구분(`working`, `warmup`), 실제 RIR(정수 0~10 또는 NULL)을 저장한다. 목표 RIR과 실제 RIR은 별개다.

## 좌우 기록

- 좌우 교대 종목의 실행 방식 스냅샷을 표시한다. 같은 중량·반복·RIR로 양쪽을 교대하면 ‘양쪽 교대’ 한 행에 한쪽당 반복수를 입력한다. 좌우 값이 다르면 왼쪽과 오른쪽을 별도 행에 기록한다. 예를 들어 왼쪽 10회, 오른쪽 8회는 두 행에 각각 10·8로 보존한다. 균등 수행이나 두 배 반복을 추정하지 않는다.
- 행 순서가 실제 기록 순서다. C4의 `(sessionExerciseId, position)` 유일키를 유지하므로 좌우는 서로 다른 position을 쓴다. 같은 세트 번호를 공유하는 좌우 쌍 모델은 아직 도입하지 않았다. 화면도 번호를 ‘행’으로 표시한다.
- 덤벨 수는 실제 사용 개수이고 수행 측과 독립적이다. 양쪽 교대의 볼륨은 아래 규칙을 따른다. 기존 수행 측의 볼륨 계산은 유지한다.
- 한쪽만 기록해도 저장할 수 있고 누락된 반대쪽을 만들지 않는다. 종목별 최대 30행은 좌우 행을 모두 포함한다.
- 이전 데이터의 수행 측은 ‘미지정’으로 유지한다. 종목의 교대/동시 설정으로 과거 수행 측을 추정하지 않는다. 실제 수행과 사전의 기본 실행 방식이 다를 수 있으므로 수행 측을 사전 설정으로 강제하지 않는다.

## 마지막 RIR

마지막 RIR은 저장 순서상 마지막으로 **수행 완료한 본세트**의 `actualRir`이다. `lastWorkingIndex`를 사용하며 NULL이 아닌 과거 값을 찾아 대체하지 않는다. 좌우가 별도 행이면 마지막에 기록한 측의 행이 기준이다.

- RIR 0은 실제 값이고 빈칸은 NULL이다. 마지막 완료 본세트에 RIR이 없으면 미입력으로 표시한다.
- 새 행은 미완료·RIR NULL로 시작한다. 미완료 행은 마지막 수행 본세트를 바꾸지 않는다. 새 본세트를 완료하면 그 행이 기준이 되고, 이전 RIR을 복사하지 않는다.
- 이후 워밍업을 완료해도 마지막 본세트 기준은 바뀌지 않는다. 워밍업 자체의 RIR은 원하면 해당 행에 기록할 수 있다.
- ‘마지막 본세트 RIR’ 입력은 해당 행의 RIR을 직접 수정한다. 별도의 요약 RIR을 저장하지 않는다.
- 완료 행 삭제는 확인하며, 본세트/워밍업 전환과 삭제 후 남은 행으로 기준을 다시 계산한다. 다른 행의 RIR은 이동시키지 않는다.
- 완료 해제 시 해당 행 RIR이 있으면 삭제 확인 후 NULL로 바꾼다. 미완료 행에 RIR을 넣은 API 요청은 거부한다.

## 저장·마이그레이션

기존 C4의 세션 버전·소유권·Origin·트랜잭션·입력 보존·PWA 업데이트 방지를 그대로 사용한다. 세트 요청에는 side/kind/actualRir가 필수다. 이 필드 없는 이전 클라이언트 요청은 400으로 거부해 새로운 RIR을 조용히 지우지 않도록 한다. 브라우저는 업데이트 후 다시 열어 사용한다.

`202610280005_sides_rir`는 기존 행에 side=unspecified, kind=working, actualRir=NULL을 추가한다. C4에서 세트 유형을 구분하지 않았던 행은 기존 본세트 취급을 유지하며, 필요하면 사용자가 워밍업으로 수정한다. RIR·좌우·반복수를 추정해 채우거나 기존 중량·반복수를 변경하지 않는다. DB에도 수행 측·세트 유형·RIR 범위와 완료 조건 제약을 둔다.

유산소·일지 메모·운동 종료는 C6, 영구 로컬 초안·내부 이동 복구는 C7이다. Notion 원본 적재는 아직 수행하지 않았다.

## 양쪽 교대 (2026-10-31)
사용자 확인: 양쪽 교대의 12회는 왼쪽12회+오른쪽12회(총24회)다. side=alternating_both, reps=12로 한 행에 저장하고 입력·텍스트보관·테스트읽기전용·이전비교에서 한쪽당/총반복을 구분한다. 좌우 중량·반복·RIR이 다르면 기존 left/right 별도행을 사용한다. 공통 RIR만 한 행에 보존하며 양측 행을 자동 생성하지 않는다.
새 모드의 외부중량 볼륨은 한쪽 중량×한쪽 반복×2다. 덤벨1개 교대/2개를 들고 교대 모두 물리적으로 수행하는 한쪽 부하를 사용하므로 덤벨 수를 다시 곱하지 않는다. 기존 side 값의 산식/입력/NULL·0/RIR·순서는 변경하지 않는다. DB CHECK는 값 하나만 확장하며 기존행 변환은 없다. 종목의 실행방식에서 과거 수행측을 추정하지 않는다.
