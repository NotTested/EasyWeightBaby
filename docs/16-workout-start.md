# C3 운동 시작·진행 중 세션 재진입

작성일: 2026-10-28 (Asia/Seoul).

## 사용 흐름

오늘 화면의 ‘운동 시작·이어서 열기’에서 진행 중인 운동을 다시 열거나 새 운동을 시작한다. 새 운동은 빈 운동 또는 본인 루틴의 저장 버전·계획 요일을 선택한다. 휴식일은 그대로 시작할 수 없으며 다른 계획 요일이나 빈 운동을 선택한다.

- 제목과 실제 운동 날짜를 지정한다. 기본 날짜는 사용자 시간대 기준 오늘이다.
- 실제 날짜와 계획 요일은 독립적이다. 토요일 계획을 일요일에 수행하는 이월 등을 표현할 수 있다.
- 시작 요청이 성공한 경우에만 상세 화면으로 이동한다. 상세 URL·진행 중 목록·오늘 화면에서 같은 ID로 재진입하고 새로고침할 수 있다.
- 새 운동은 진행 중 상태로 시작하고 실제 서버 시작 시각과 사용자 시간대를 보존한다. 이전 레코드의 알 수 없는 시작 시각은 NULL로 유지하고 화면에 미기록으로 표시한다.
- 같은 날 여러 운동을 허용한다. 날짜나 루틴이 같다고 기존 세션과 자동 병합하지 않는다. 먼저 진행 중 목록을 확인하도록 안내한다.

## 저장·스냅샷·권한

추가 마이그레이션 `202610280003_workout_start`로 시작 요청 키·해시·시작 시각·루틴 출처를 확장하고 SessionExercise를 추가했다. 기존 세션은 유지하며 실제 수행 세트는 아직 생성하지 않는다.

- POST `/api/sessions`: strict 입력·Origin·인증을 확인하고 서버가 소유자·시간대·시작 시각·진행 상태를 결정한다. 클라이언트가 해당 필드를 주입할 수 없다.
- 루틴은 본인 소유의 명시한 버전과 요일을 읽는다. 비활성·비반복·타인 개인 종목을 포함하면 시작을 거부한다. 가져올 목표 순서·이름·도구·세트/반복·목표 RIR·각도·메모를 SessionExercise에 복사한다. 수행 방식·측정 방식은 시작 시 종목 상태를 보존한다.
- 루틴 버전 참조는 유지하며 시작 후 루틴·종목 변경으로 이미 가져온 목표를 덮어쓰지 않는다.
- 상세에는 ‘계획 목표’, ‘실제 수행 기록이 아님’을 표시한다. 목표를 완료 세트나 실제 운동량으로 계산하지 않는다.
- GET `/api/sessions/:id`, `/sessions/:id`는 본인만 접근할 수 있다. 관리자도 타인 세션에 접근할 수 없다. API 응답은 no-store이며 요청 해시·재시도 키는 반환하지 않는다.
- GET `/api/sessions?status=in_progress`는 본인 진행 중 목록이며 기본 all은 기존 일지 목록을 유지한다. API·시작 화면은 최대 100개, 오늘의 진행 중 요약은 10개다. 일지의 달력·검색·페이지 이동은 D단계다.

## 재시도

시작 요청에는 사용자 범위 UUID 키를 사용한다. 정규화한 본문 해시와 함께 저장하며 같은 키·같은 본문은 원래 ID를 반환한다(최초 201, 재사용 200). 같은 키의 다른 본문은 409다. DB 유일키와 트랜잭션으로 동시 요청에서도 한 건만 생성한다.

시작 폼은 같은 내용으로 재시도할 때 현재 페이지의 키를 재사용한다. 입력을 바꾸면 새 키를 만든다. 연결 오류는 저장 실패로 단정하지 않고 진행 중 목록 확인 또는 같은 내용 재시도를 안내한다. 키를 브라우저 종료·새로고침 이후까지 보존하는 초안 기능은 C7 범위이므로, 새로고침 후에는 진행 중 목록에서 기존 운동을 확인한다. 오프라인 시작·자동 재전송은 제공하지 않는다.

편집·시작 요청 중에는 PWA 업데이트를 막고, 초기 기본값만 있는 폼은 안전 표시한다. 계획을 불러오는 중이거나 휴식일이면 시작하지 않으며 서버에서도 다시 검증한다.

## 검증

```bash
cd /workspace/EasyWeightBaby
npm run db:generate
npm run db:deploy
npm test
npm run test:integration
npm run test:browser
npm run build
npm run test:production
npm run test:pwa
```

테스트는 별도 _test DB에서 생성한 세션을 먼저 제거한 후 루틴·종목·계정을 정리한다. 개발 DB와 기존 사용자 기록은 초기화하지 않는다.

신규 단위 검증은 실재 날짜·윤년·금지 필드를 확인한다. HTTP는 동시 재시도 한 건 생성, 본문 충돌, 별도 키 새 세션, 실제 날짜/계획 요일 분리, 루틴·종목 변경 후 스냅샷 유지, 비활성 참조 거부, 저장 후 재시도, 타인·관리자 접근 차단을 확인한다.

브라우저는 1280/320px에서 빈 운동 시작·새로고침·진행 중 목록 재진입·휴식일 차단·루틴 운동 시작·목표 표시와 가로 넘침 없음을 확인했다. 최종 결과는 단위 4개, HTTP 23개, 브라우저 14개, 운영 3개, PWA 5개 pass, fail/skip 0이다. 운영 빌드·타입 검사와 개발 DB/모델 차이 없음도 확인했다.

다음 C4는 종목·가변 세트의 실제 중량·덤벨 수·반복을 저장·재조회하는 작업이다. 목표와 실제를 별도로 저장하고 실제 수행 완료 여부도 분리해야 한다. 마지막 RIR·좌우 기록은 C5, 운동 종료는 C6다.
