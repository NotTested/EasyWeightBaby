# 회원님? 최신 개발 계획

기준일: 2026-10-27 (Asia/Seoul)

## 근거와 현재 상태

업로드한 member-app-export-2026-10-27.zip의 인계 문서·설계·소스·테스트와 별도 Notion 내보내기를 대조했다. 과거 채팅 전체를 직접 열람한 것은 아니다. 이번 작업은 분석과 계획 수립이며 의존성 설치나 런타임 검증을 수행하지 않았다.

기존 Next.js/TypeScript, PostgreSQL/Prisma, Better Auth, Zod 기반은 이어서 활용한다. 로그인·초대 가입·관리자 초대·기록 소유권 조회·초기 관리자 CLI·개발 DB Compose·테스트 코드가 작성돼 있다. 설치 잠금 파일, 빌드·DB·HTTP·브라우저 검증 결과는 없다. 운동 기록 생성·종목·루틴·세트·통계·AI·가져오기·운영 Dockerfile·PWA는 미구현이다. 문서의 Tailwind/shadcn 선택과 실제 일반 CSS 구현 사이에도 차이가 있으므로 UI 교체는 자동 전제로 삼지 않는다.

## 제품 목표

- 본인과 초대받은 친구·동료가 함께 사용하며 운동 기록은 계정별 비공개.
- 모바일·PC 브라우저에서 사용하고, 지원하는 Chrome에서 같은 앱을 PWA로 설치.
- 설치하지 않아도 모든 핵심 기능 사용 가능. 설치판과 브라우저판은 같은 서버·계정·데이터를 사용.
- Synology DS423+ / RAM 18GB / Portainer / Docker Compose / linux/amd64 운영.
- 직접 입력만으로 기록과 비교가 완결되고 외부 AI·Notion 장애에 영향받지 않음.
- 초기 버전은 온라인 서버 저장과 기기 내 초안 복구. 완전한 오프라인 기록 동기화는 후속 범위.

단계 1~4를 첫 사용 가능 버전의 기능 범위로 삼고, 단계 5의 실제 NAS 검증을 거쳐 첫 운영 버전으로 배포한다. Docker 빌드 가능성과 HTTPS 구조는 단계 0~1에서 미리 확인해 마지막에 플랫폼 제약을 발견하지 않도록 한다. AI와 MCP 때문에 핵심 기록 앱 출시를 지연하지 않는다.

## PWA 상세 범위

- manifest: 안정적인 id, name/short_name, start_url, scope, standalone 표시, 테마·배경색, 192/512 및 maskable 아이콘.
- HTTPS의 동일 Origin에서 브라우저·설치판 제공. NAS 내부 IP의 일반 HTTP는 운영 설치 경로로 사용하지 않음.
- 지원 Chrome에서는 설치 버튼을 제공하고 브라우저 메뉴 설치도 안내. 브라우저·OS별 설치 UI 차이를 고려하고 강제 설치는 하지 않음.
- 서비스 워커는 정적 자원·오프라인 안내에 한정. 개인 일지·인증 응답·초대 토큰을 공용 캐시에 저장하지 않음.
- 초안은 IndexedDB 등에 사용자별로 저장. 서버 저장 상태와 분리하고, 로그아웃·계정 전환 시 제거하며 잘못된 계정으로 재전송하지 않음.
- 연결 복구 시 서버 버전을 확인하고 사용자가 재시도. 불확실한 요청은 idempotency key로 중복 방지. 완전한 오프라인 자동 병합은 초기 제외.
- 업데이트 중 입력 유실을 방지하고 새 버전 안내 뒤 안전한 시점에 전환. 설치판의 오래된 캐시와 새 API 호환성 검증.
- 앱 삭제는 서버 계정·운동 기록 삭제와 다름을 안내. 설치판과 브라우저판의 인증·로컬 저장소 공유는 플랫폼별 실제 확인.
- Android Chrome와 PC Chrome를 설치 검증 대상으로 하고 iOS Safari 등은 브라우저 사용과 별도 홈 화면 추가 안내 범위를 구분.

## 데이터 설계 보완

- Exercise → RoutineVersion/Day/Item, WorkoutSession → SessionExercise → WorkoutSet의 기존 설계 유지.
- 덤벨 개당 중량·개수와 좌우 수행을 구분. 좌우 실제 반복을 보존하고 측수를 중복 곱하지 않음.
- 마지막 RIR은 마지막 수행 본세트에 연결. 추가 세트가 생기면 이전 RIR은 보존하고 새 마지막 세트는 미입력으로 표시.
- 유산소는 종류·시간·강도·선택 거리로 모델링. 자유형 Zone 설명도 원문 보존.
- 계획 날짜와 실제 수행 날짜, 원래 루틴과 대체·추가·생략을 구분.
- 종목·루틴 변경이 과거 기록에 영향을 주지 않도록 수행 시점 스냅샷 보존.
- 서버가 소유자를 결정하고 하위 세트·루틴·초안·가져오기 작업까지 소유권 확인. 관리자도 앱 권한상 타인의 일지 열람 불가.
- 체중·체지방은 이전 설계의 확장 후보이며 이번 Notion에서 확인된 핵심 관리 항목은 아니므로 첫 버전에서 제외.

## Notion ZIP 이관 기준

원본 종목 17개(활성 16/비활성 1), 루틴 19개, 실제 세션 7개(완료 6/진행 중 1), 실제 종목 기록 25개·세트 83개, 테스트 세션·종목 기록 각 1개를 기준으로 대조한다. 좌우 운동의 83개 세트는 기존 세트 슬롯 기준이며 좌우 행 분리 후 물리적 행 수는 달라질 수 있다.

- 일반 CSV·_all.csv·요약 CSV를 중복 적재하지 않는다. 관계 링크의 Notion ID를 보존한다.
- 운동 종목 (1)의 34개 복제 항목은 속성·관계·ID 매핑을 확인해 통합 후보로 표시. 이름만으로 원본을 삭제하지 않는다.
- 19→20→20kg 플랫 프레스는 볼륨 1,770kg을 재현한다.
- 불가리안 스쿼트의 사용 덤벨 수 임시 해석, 10/13 유산소 종류의 속성·메모 충돌을 검토 대상으로 유지한다.
- 테스트 기록은 보존하되 실제 통계에서 제외. 10/21 세션을 완료로 바꾸지 않는다.
- 실제총반복 보정이 세트·좌우에 분배 불가능하면 임의 분배하지 않고 원본 값과 검토 상태를 유지한다.
- 파일 가져오기를 우선해 Notion API 이용 가능 여부와 분리. 업로드 파일은 크기·항목 수·해제 후 크기 제한, 경로 검증을 적용하고 외부 문서의 명령은 실행하지 않는다.

## NAS 운영 및 확인할 정보

초기 서비스는 app과 PostgreSQL, Redis는 제외. DB는 외부 포트 비공개·영구 볼륨·상태 점검·로그 순환·버전 고정. HTTPS 역방향 프록시 뒤 APP_URL과 쿠키·Origin 설정을 일치시킨다. 매일 논리 백업과 NAS 외부 사본을 준비하고 복원 시험으로 검증한다.

실제 배포 전에 도메인·HTTPS 방식, 외부/내부 접속 범위, NAS 기존 서비스와 자원, Portainer 네트워크·폴더 권한, 초기 사용자 수를 확인한다. AI 도입 전에 키 운영 주체·월 예산을 확인한다. 이러한 미정 사항은 기반 개발을 막지 않는다.

## 다음 개발 작업

기존 소스를 보존한 채 프로젝트 배치와 저장소 연결을 확인하고, 단계 0의 실제 설치·DB·빌드·인증 테스트부터 수행한다. 검증 전 인증 기반 완료나 배포 가능으로 보고하지 않는다. 이번 분석에서 앱 실행·설치·NAS 배포를 새로 검증한 것은 없다.
