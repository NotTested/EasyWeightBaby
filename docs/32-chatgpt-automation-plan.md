# EasyWeightBaby ChatGPT 연동·자동화 상세 개발 계획

기준: 2026-10-31 Asia/Seoul. 상태: 계획 확정용 작업 분해 완료, 아래 신규 구현·계정 연결·예약 생성은 미실행.

## 2. 목표와 구현 경계

1. ChatGPT에서 본인의 운동일지·종목 이력·주간 요약 조회.
2. 자연어를 검토 가능한 입력 초안으로 변환하고 사용자의 명시적 확인 후 저장.
3. 읽기 전용 주간 요약·조건부 미기록 알림을 예약 실행.
4. 기존 직접 입력·사용자별 비공개·NULL/0·RIR·좌우 의미·백업 유지.

이 계획은 예약 작업 생성이나 새 외부 접근 권한 부여 자체를 승인한 것으로 취급하지 않는다. 실제 연결 시 필요한 사용자 로그인·동의·앱 지원 여부를 확인한다. 루틴/실제 기록 자동 변경, 대화 전체 수집, 무인 확정 저장, 원본 Notion 양방향 동기화는 제외한다.

## 3. 권장 구조

ChatGPT 수동 대화 / 예약 작업 → 사용자별 OAuth → EWB MCP 도구 → 공통 서비스 계층 → PostgreSQL.
기존 브라우저 UI는 세션 쿠키·Origin 검증을 계속 사용한다. MCP는 별도 OAuth 토큰 검증을 통해 동일한 owner context를 주입하며 쿠키·비밀번호를 공유하지 않는다. MCP 핸들러에서 DB를 직접 우회 호출하지 않는다.
읽기 도구: list_workouts, get_exercise_history, get_weekly_summary. 쓰기 도구는 prepare_workout_draft와 confirm_workout_draft를 분리한다. 통계 수치는 서버가 계산하고 모델은 근거가 붙은 설명만 작성한다.
OpenAI API를 앱 내부에서 호출하는 기능은 선택적 F3다. MCP만 사용하는 경로와 별도로 키·비용·전송 동의를 검토하며, ChatGPT 구독과 API 사용 권한이 자동으로 같다고 전제하지 않는다.
NAS의 백업·서비스 상태 점검은 NAS 자체 실행을 유지한다. ChatGPT의 요약 작업이 실패해도 기록 저장·백업이 계속돼야 한다.

## 6. 릴리스와 실제 개발 착수 순서

- R0 기반: F0-01 → F0-02 → F0-03. 외부 접근을 늘리기 전 호환성과 권한을 확정한다.
- R1 읽기 연동: F4-01 → F4-02 → F4-03 → F4-04 → F4-05 → F4-06 → O1-01. 본인 조회가 끝나야 예약으로 이동한다.
- R2 요약 자동화: A1-01 → A1-02 → A1-03. A1-04는 별도 opt-in. 실제 일정은 아직 미지정이며 예약을 만들지 않는다.
- R3 규칙 입력: F1-01 → F1-02 → F1-03 → F2-01~05 → O1-01. 브라우저 내 자연어 초안부터 독립적으로 사용할 수 있다.
- R4 ChatGPT 입력: F5-01 → F5-02 → O1-01. 초기에는 앱 내 확인을 기본으로 하며 무인 확정은 제공하지 않는다.
- R5 선택 AI: F3-01~03 → O1-01 → O1-02. API 사용 의사가 확정되지 않으면 보류하고 R1~R4로 사용한다.

각 릴리스에서 O1-01을 반복하되 변경 없는 전체 검사를 무조건 반복하지 않는다. 권한/스키마/저장에 영향을 주면 DB·HTTP·브라우저 검증을, 순수 파서에는 단위·자원 검증을 적용한다. 문서만 바꾸는 작업은 링크·번호·선행 관계 검사로 충분하다.

## 7. 자동화 계약과 장애 처리

주간 요약 후보: 매주 선택한 요일/시간, 직전 완료 주간을 조회해 운동일수·종목별 수행·비교 가능한 변화·누락 한계와 원본링크를 전달한다. 주간 시작 요일은 ISO 월요일을 기본 제안으로 하고 사용자 선택을 기록한다. 진행 중 기록을 완료 실적으로 섞지 않는다.
조회 도구의 재호출은 허용하되 전달 중복은 실행구간 키로 차단한다. 토큰 철회/만료는 재로그인 필요로 보고하며 브라우저 비밀번호·세션 추출로 우회하지 않는다. 데이터가 없는 경우와 조회 실패는 다른 상태다.
미기록 알림은 계획된 운동일이 있을 때만 후보로 만들고 일정/알림 수신시간/진행중 예외를 확정한다. 원본 기록·루틴은 변경하지 않는다.
중요 장애에는 NAS 자체 상태 신호를 사용한다. ChatGPT가 백업을 실행하는 유일한 경로가 되지 않는다. 외부알림 채널·보존정책·독립장치 키사본은 기존 운영 후속 항목으로 유지한다.

## 8. 보류 결정과 다음 착수 단위

확인이 필요한 것은 실제 MCP/예약 지원 계정·클라이언트, OAuth 제공 방식, 조회 데이터 전송 범위, 예약 요일·시간·알림 채널, AI API 사용 여부다. 전체 개발을 멈추고 한꺼번에 질문하지 않고 각 의존 작업에서 결정한다. 공개 범위나 자격 증명을 새로 만드는 단계에서는 해당 연결의 실제 접근 범위를 사용자에게 설명한다.
다음 착수는 F0-01이다. 계획 작성만으로 구현·MCP연결·토큰발급·예약·NAS배포를 수행하지 않았다.
