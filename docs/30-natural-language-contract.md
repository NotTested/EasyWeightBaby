# F1 자연어 운동 기록: 입력·출력 계약

작성일: 2026-10-31 (Asia/Seoul). 상태: 계약·타입·합성 사례 준비, 규칙 파서 구현 전.
코드: src/lib/natural-workout-contract.ts. 타입은 계약을 표현하며 런타임 검증을 대신하지 않는다.

## 범위

F1은 외부 AI 없이 원문에서 검토용 초안을 만드는 순수 규칙 파서다. 이 작업 단위에서는 계약과 사례만 정의한다. 파서 함수, UI/API, DB 쓰기, 계정/종목 조회, AI 키/과금, MCP는 추가하지 않는다.
후속 파서도 DB·인증·네트워크·시계에 의존하지 않으며 원문을 로그에 쓰지 않는다. 현재 실제 저장 입력 ActualInput과는 다른 구조를 사용한다. 초안이 만들어져도 저장·수행 완료를 의미하지 않는다.

## 입력과 접근 범위

RuleDraftRequest는 text와 catalog만 받는다. 호출자가 현재 사용자에게 허용된 종목만 catalog에 전달해야 한다. 순수 파서는 접근 권한을 증명하지 않는다. 미래의 저장 단계에서 종목·소유권·version을 다시 확인해야 한다.
카탈로그에는 id, version, 이름, 별칭, 장비, 수행 방식, 측정 방식, active만 포함한다. 다른 계정 정보/설명/개인 기록/비밀값은 전달하지 않는다.
입력 객체를 변경하지 않는다. 카탈로그 id 중복/빈 식별자/잘못된 버전/허용되지 않은 필드 구조 등은 catalog_invalid로 거부한다. 비활성 종목은 자동 선택하지 않는다.

## 원문과 필드 상태

정상 범위의 sourceText는 원문을 그대로 보존한다. TextSpan은 JavaScript UTF-16 코드 단위의 [start,end)이며 0 <= start < end <= sourceText.length다. 모든 evidence는 비어 있지 않은 실제 원문 구간이어야 한다. 줄바꿈 CRLF, 한글, 이모지, NFKC 변환으로 인덱스를 바꾸지 않는다. 정규화된 문자열의 인덱스를 원문 인덱스로 오인하지 않는다.
필드 상태는 explicit(value+근거), missing, ambiguous(후보+근거), invalid(근거)다. 누락과 명시한 0을 구분하며 NULL/0/빈 문자열을 대신 채우지 않는다.
종목은 기존 normalizeExerciseName(NFKC·공백 정리·소문자)로 이름/별칭을 대조한다. 일치하는 활성 종목 id가 하나면 matched, 다른 id가 여럿이면 ambiguous, 없으면 unmatched다. 동일 id의 이름/별칭 중복은 같은 후보로 취급한다. 부분·퍼지 매칭으로 종목을 확정하지 않는다.
이름이 겹치는 카탈로그 후보는 이름 또는 별칭 우선순위로 임의 선택하지 않는다.

## 출력과 저장 경계

유효 범위의 결과는 항상 needs_review/confirmationRequired=true다. 인식된 값만 있어도 자동 저장 가능 상태를 반환하지 않는다. 입력/카탈로그/출력 한도 위반은 rejected이며 원문이나 카탈로그를 결과로 반사하지 않는다.
issues는 안정적인 code/severity/path/evidence로 표현한다. 화면용 문구는 후속 UI에서 만든다. 미해석 문장은 unparsed 구간으로 보존하며, 일부 숫자를 인식했다고 나머지를 조용히 버리지 않는다.
recognized set/cardio의 reportedCompleted는 원문이 명시한 수행 여부일 뿐, 저장 API의 completed가 아니다. 값만 입력된 세트를 수행 완료로 추측하지 않는다. 저장 단계에는 사용자 확인과 기존 actualSetSchema/cardioRecordSchema 검증이 필요하다.

## 기존 의미 보존

- 중량 0~2000kg, 반복 0~1000의 정수, 덤벨 개수 1/2, RIR 0~10의 정수. NaN/Infinity/음수/상한 초과를 허용하지 않는다. 범위를 넘은 값을 잘라내거나 절댓값으로 바꾸지 않는다.
- 덤벨 중량은 개당 값이다. 개수가 명시되지 않으면 장비·양측 수행·과거 기록으로 2개를 채우지 않는다. 중량에 덤벨 개수나 좌우를 곱해 원래 값을 덮어쓰지 않는다.
- side는 unspecified/both/left/right, kind는 working/warmup이다. 원문에 없는 필드는 missing으로 두며 bilateral/alternating이라는 종목 속성만으로 좌우 수행 행을 만들지 않는다.
- 좌우 값이 다르면 서로 다른 세트 행으로 보존한다. 원문 순서는 유지하며 미수행·워밍업을 실제 수행 본세트에 합치지 않는다.
- RIR은 적용 대상이 명확한 세트에만 actualRir로 둔다. '마지막 RIR 2'는 last_performed_working 힌트로 보존하고, 마지막 수행 본세트가 확정되기 전에는 행에 임의 배정하지 않는다. 대상 없는 RIR은 unresolved 힌트와 unassigned_rir로 남긴다.
- 날짜는 실제 존재하는 명시적 YYYY-MM-DD만 인식한다. 누락/오늘/어제는 F1에서 날짜를 추정하지 않는다. docs/03-screens.md의 '오늘을 초안으로 표시'는 후속 UI가 사용자 시간대 기준으로 제안하고 확인받을 동작이며 파서가 명시 날짜로 위조할 값이 아니다.
- 유산소의 시간 0~1440분·거리 0~1000km, 활동명/강도/메모 길이는 기존 cardioRecordSchema를 따른다. 종류/단위가 없는 숫자를 추측하지 않는다. lb 등 지원하지 않는 단위는 F1에서 임의 환산하지 않는다.

## 자원 한도

원문 10,000 UTF-16 코드 단위, 200줄, catalog 1,000개, 종목 40개, 종목당 세트 30개, 유산소 20개, issue 200개를 한도로 한다. 넘으면 rejected/output_limit로 명확히 반환하고 부분 출력만 정상처럼 반환하지 않는다.
카탈로그 별칭/이름/속성은 기존 exerciseFields의 길이·개수·enum 범위로 제한한다. 한도 검사는 큰 배열 확장/정규식/정규화 전에 한다. 반복 세트 확장도 세트 개수를 먼저 검증한다. 중첩 반복으로 입력 크기에 비해 폭발하는 정규식을 사용하지 않는다.
빈 입력은 rejected/input_empty. 너무 큰 입력/카탈로그는 evidence=[]로 원문 반사 없이 거부할 수 있다. 텍스트 내부 문제가 있는 정상 크기 입력은 해당 구간을 표시한다.

## 파서 구현 시 사용할 합성 사례

아래는 예정된 인수 기준이며 이번에 실행된 파서 테스트 결과가 아니다. 모든 종목은 합성 활성 카탈로그로 제공한다.

| 입력 | 기대 해석/확인 사항 |
|---|---|
| `2026-10-31` + 줄바꿈 + `벤치프레스 20kg 10회 3세트` | 명시 날짜·중량·반복·세트 수 인식. 3행 확장, 수행 완료/장비 개수/좌우/본세트 여부는 추정하지 않음 |
| `RDL 19kgx2 15 15 15 RIR 2` | 덤벨 카탈로그의 제한된 compact 문법에서 개당 19kg·2개·반복 3행. 대상이 불명확한 RIR은 힌트로 보존, 수행 완료 추정 없음 |
| `RDL 19kg 15회` | 덤벨 개수 missing, 이전 기록으로 보충하지 않음 |
| `불가리안 스쿼트 왼쪽 12kg 8회; 오른쪽 12kg 7회` | 명시된 좌우·원문 순서·서로 다른 반복 보존. 세미콜론은 한 종목 안의 명시 세트 구분 |
| `벤치프레스 0kg 0회` | 0을 missing으로 바꾸지 않음. 수행 여부는 별도 확인 |
| `벤치프레스 -20kg 10회` 또는 `벤치프레스 20kg 2.5회` | 해당 구간 invalid/out_of_range, 20 또는 2로 오독하지 않음 |
| `프레스 20kg 10회` (서로 다른 두 종목이 같은 별칭) | exercise ambiguous, 후보를 모두 검토 대상으로 유지 |
| `2026-02-30` 또는 `어제 RDL 19kg 15회` | 잘못된 날짜 표시 또는 상대 날짜 미해석. 오늘로 바꾸지 않음 |
| `러닝 20분 3km Zone 2` | 명시 시간·거리·강도와 원문 보존. 수행 완료 추정 없음 |
| `벤치프레스 20kg x 10` | 문법이 지원되거나 의미가 유일함을 확인하기 전에는 bare x의 의미를 추정하지 않음 |
| 한도 초과 세트·원문·카탈로그, NFKC로 길이가 바뀌는 문자, 이모지/CRLF | 큰 할당 전 거부 및 원문 evidence 인덱스 검증 |

F1 최초 문법은 명시 단위/세트 수, 명시 좌우, 문서화된 compact 문법으로 제한한다. 단위 없는 자유형 문장의 지원 범위는 사례와 함께 명시적으로 추가한다.
