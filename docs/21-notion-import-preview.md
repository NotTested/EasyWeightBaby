# D1 Notion 이관 미리보기

D1은 ZIP → 원본 보존 staging → 검증 보고서까지만 수행한다. DB 연결·적재·앱 업로드 API는 없으며, 문서 안의 운영 지침/명령은 실행하지 않는다. C6~C7 미커밋 변경은 보존했다.

## 실행

Python 3 표준 라이브러리만 사용한다. 새 의존성은 없다.

```sh
npm run notion:preview -- /path/to/notion-export.zip --output /workspace/reports/my-preview
npm run test:import
```

출력은 summary.json(집계·파일 목록)과 staging.json(원본 CSV 필드·연결된 Markdown·원본 ID·매핑 후보·검토 항목)이다. 출력 파일은 0600으로 생성하고 기존 파일은 덮어쓰지 않는다. 개인 메모가 있으므로 Git에 넣지 않는다. 저장소 안에서 생성할 때는 무시 경로 reports/notion/ 아래를 사용한다. 원본 ZIP은 변경하지 않는다.

CLI 종료 코드: 0은 구조 검증 오류 없음, 2는 보고서 생성 후 검증 오류 발견, 1은 ZIP/인코딩/입출력 등 처리 실패다. 종료 코드 0도 적재 승인이나 검토 완료를 뜻하지 않으며 canApply는 항상 false다.

## 파일·ID 처리

- ZIP 32 MiB, 항목 2000개, 해제 합계 32 MiB, 개별 파일 2 MiB, 압축 비율 500배를 제한한다. stored/deflate만 지원한다.
- 절대 경로·상위 경로·역슬래시·Windows 드라이브·퍼센트 인코딩된 위험 경로·심볼릭 링크·중복 파일명·암호화·중첩 ZIP을 거부한다. 파일을 디스크에 해제하지 않는다. UTF-8/BOM과 표준 CSV 따옴표·쉼표·줄바꿈을 처리한다.
- 원본 5개 테이블의 _all.csv를 우선 선택하고 일반 CSV는 공통 필드/관계 ID를 대조한다. 동일 관계의 .md/.csv 링크와 상대 경로 차이는 ID 기준으로 비교한다. 실제 값 충돌은 오류로 남긴다. 요약 CSV는 목록만 보고하며 적재 후보에서 제외한다.
- Markdown 파일명의 32자리 ID를 같은 테이블의 CSV 제목과 연결한다. 후보가 없거나 복수 ID면 선택하지 않는다. 제목은 ID를 찾기 위한 연결 단서이며, 이름만으로 다른 ID를 통합하지 않는다. ID가 같은 동일 행만 중복 제거한다. 같은 ID의 다른 값은 둘 다 보존하고 오류로 표시한다.
- 복제 종목 34개는 원본과 별도로 보존한다. 동일 이름 그룹은 후보일 뿐 승인된 ID 매핑이 아니다.
- 로그→세션/종목, 루틴→종목, 세션→로그 관계의 ID/종류와 로그·세션 날짜/기록 구분을 대조한다. 미해결 관계와 잘못된 날짜·숫자는 오류다. 쉼표를 잘못 쓴 숫자를 임의로 복원하지 않는다.

## 필드 매핑과 보류 규칙

| 원본 | 미리보기 |
|---|---|
| 종목명·도구·분류·수행방식·측정방식·활성 | 앱 enum/필드 후보. 알 수 없는 값은 검토 |
| 요일·수행순서·목표 세트/반복·벤치·메모 | 루틴 항목 후보. 전체 주간 버전/휴식일을 임의 생성하지 않음 |
| 기록 구분·날짜·진행 상태 | actual/test/plan과 ISO 날짜 및 상태 후보. 테스트의 ‘계획’ 상태도 원문 보존 |
| 1~4세트·기본/세트별 kg | 원본 슬롯과 중량 출처. 빈칸은 NULL, 실제 0은 0 |
| 마지막 RIR | 값과 마지막 채워진 슬롯 후보. 수행/본세트 확정 전 실제 세트에 배치하지 않음 |
| 측수·실제총반복 보정 | 원본 보존 및 검토. 좌우 반복 자동 분배 금지 |
| 유산소 종류·분·강도 | 원문 대조용 후보. 완료 여부 추정 금지 |

숫자 후보는 Decimal 기반 문자열로 출력해 원본 정밀도를 보존한다. 앱에 바로 전송할 JSON payload가 아니다. 세트별 중량 빈칸에는 기본 중량을 후보로 사용하되 weightSource로 명시한다. 명목 볼륨은 슬롯별 중량×반복×원본 덤벨 수×원본 측수의 재현 계산이며 실제 좌우 행을 생성하거나 측수를 다시 곱하는 적재 로직이 아니다. 기존 총반복 보정은 세트로 분배하지 않는다.

## 제공된 원본 결과 (2026-10-29)

- 원본 종목 17개: 활성 16, 비활성 1. 원본 ID 확인은 16개이며 비활성 ‘덤벨 컬’은 대응 Markdown이 없어 보류한다. 새 Notion ID를 만들지 않는다.
- 복제 종목 34개 유지, 동일 이름 통합 후보 17그룹. 루틴 항목 19개.
- 실제 세션 7개: 완료 6, 진행 중 1. 실제 수행 기록 25개, 원본 세트 슬롯 83개. 테스트 세션/기록 각 1개 별도 보존.
- 19→20→20kg 플랫 프레스의 명목 볼륨 1,770kg 재현. 10/21 진행 상태는 유지한다.
- 구조/관계 검증 오류 0. 검토 표식: ID 미확인 1, 기록 구분 모델 차이 2, 유산소 원문 대조 6, 수행/마지막 RIR 연결 26, 좌우 분배 3, 불가리안 덤벨 수 1. 서로 겹치는 표식이며 고유 항목 수로 합산하지 않는다.

## D2 전제와 검증

현재 앱에는 원본 ID 이관 이력과 실제/테스트/계획 구분 필드가 없으므로 D1 staging을 바로 적재하면 안 된다. D2에서 승인된 ID 매핑·검토 해결 내역과 기록 구분/멱등 이관 모델을 먼저 준비하고, 테스트 DB dry-run으로 나눈다. 미확인 ID·좌우·유산소 속성/메모 충돌·RIR 연결을 임의로 고치지 않는다.

합성 데이터 테스트 7개로 NULL/0/RIR·가변 중량·원문 줄바꿈, 중복 CSV 링크 차이/충돌, 모호한 ID, 중복 ID, 누락 테이블, 위험 ZIP, 잘못된 숫자·날짜·관계, CLI 출력/덮어쓰기 거부를 검증했다. 실제 개인 원본이나 생성 staging은 테스트 fixture로 커밋하지 않는다. 기존 앱 단위 8개도 통과했으며 웹 코드는 변경하지 않아 브라우저/운영 빌드는 이번 단계에서 재실행하지 않았다.
