# C2 버전 있는 주간 루틴

작성일: 2026-10-28 (Asia/Seoul).

## 범위

루틴 화면에서 새 계획을 만들고 월~일 휴식 여부, 운동 순서, 목표 세트·최소/최대 반복, 선택적 목표 RIR, 벤치 각도·메모를 편집한다. 종목 검색으로 활성 공용·내 종목을 선택 목록에 추가한다. 현재 C2는 반복수 종목만 지원하며 시간·거리 목표는 추가하지 않았다. 운동 시작·수행 기록·Notion 이관은 후속 단계다.

루틴당 7일, 운동일에는 1~20개 종목을 지정한다. 휴식일에는 종목을 두지 않는다. 세트 1~20, 반복 1~1000 범위이며 최소≤최대, RIR은 미입력 NULL 또는 실제 입력한 0~10을 구분한다. 휴식일로 바꿀 때 기존 항목이 있으면 지울지 확인한다. 종목 추가·제거와 위/아래 이동은 키보드 버튼으로도 조작할 수 있다.

## 모델·권한·버전

- Routine: 소유자와 현재 버전, 현재 이름. RoutineVersion: 저장 시점 이름과 버전 번호. RoutineDay: 요일·휴식. RoutineItem: 순서·종목 참조·목표·저장 시점 종목 이름/도구.
- `202610280002_routines`는 추가 마이그레이션이며 기존 수행 기록을 변경하지 않는다.
- POST `/api/routines`는 1번 버전을 생성한다. PATCH `/api/routines/:id`는 전체 계획과 현재 version을 받아 트랜잭션에서 버전 번호를 비교하고 새 버전만 추가한다. 같은 버전의 동시 저장은 하나만 성공하고 나머지는 409다.
- GET `/api/routines/:id?version=N`은 해당 스냅샷을 읽는다. 과거 스냅샷을 수정하는 API는 없다. 화면은 이전 버전을 읽기 전용으로 제공하고 최신 버전 열기로 돌아간다. 이전 버전 복원을 자동 저장하는 기능은 없다.
- 루틴 이름·목표·순서를 바꾸거나 C1 종목을 이름 변경·비활성화해도 저장된 이전 버전은 바뀌지 않는다. 버전의 종목 이름·도구는 DB에서 읽어 서버가 저장하며 클라이언트 스냅샷 주입은 거부한다.
- 관리자도 타인의 개인 루틴을 읽거나 편집할 수 없다. 종목은 본인 또는 공용이면서 활성·반복 측정인지를 서버에서 확인한다. 기존 종목이 비활성화됐다면 새 버전 저장 전 교체해야 한다. 이전 버전 조회는 계속 가능하다.
- 삭제·공유·소유권 이전 API는 이번 범위에 없다. 루틴 목록은 최근 100개, 화면의 버전 선택 목록은 최근 50개다. 더 오래된 버전도 삭제하지 않으며 번호를 지정한 API로 읽을 수 있다.

## 입력·업데이트

편집 중 선택을 바꾸면 미저장 내용을 버릴지 확인하고, 저장 실패·충돌 시 입력을 유지한다. 서버가 저장을 확인한 뒤 목록 갱신만 실패한 경우도 저장 실패와 구분해 안내한다. 변경·처리 중에는 PWA 업데이트를 차단하며, 서버 확인이 끝난 폼만 안전 표시를 한다. 오프라인 자동 저장·브라우저 종료 후 초안 복원은 아직 없다(C7).

기존 API의 16KiB 제한은 유지하고 루틴 API에만 256KiB 한도를 적용했다. 항목 수·문자 길이는 별도로 검증한다. 장비·유산소·세트 실제 수행 결과를 목표 계획으로 추정해 저장하지 않는다.

별도 테스트 DB에서 생성한 루틴부터 제거한 후 테스트 종목·계정을 정리한다. 실제 사용자 데이터와 이전 마이그레이션은 보존한다.

루틴 HTTP 검증: 권한·Origin·소유자 주입·다른 사용자의 개인 종목 및 비반복 종목 참조 거부, 공용/개인 종목 사용, 동시 저장, 이전 순서/목표/이름 보존, 비활성 종목 저장 거부와 버전 미증가를 확인한다.

브라우저 검증: 1280/320px에서 작성→두 종목 순서 변경→v1 저장→목표/이름 변경→v2 저장→v1 읽기 전용 조회→최신 버전 복귀→새로고침 후 재조회와 가로 넘침 없음을 확인했다. 최종 통과 결과는 단위 3개, HTTP 18개, 브라우저 11개, 운영 3개, PWA 5개이며 fail/skip은 0이다. 운영 빌드·타입 검사와 개발 DB/모델 차이 없음도 확인했다.

다음 C3는 빈 운동 또는 루틴으로 실제 운동을 시작하고 진행 중 세션에 재진입하는 기능이다. 계획 버전·목표 스냅샷을 실제 기록과 분리해야 한다.
