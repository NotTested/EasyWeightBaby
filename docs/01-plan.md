# 단계별 작업계획과 기술 선택

## 확정된 요구

- 사용자: 본인과 초대받은 친구·동료.
- 장비: DS423+, RAM 18GB. Portainer로 Docker Compose 스택 운영.
- 기록: 종목, 세트별 무게·반복, 종목별 마지막 세트 RIR, 주간 루틴.
- 입력 예: `RDL 19kgx2 15 15 15 RIR 2`.
- Notion 기록을 활용하고 ChatGPT 연동을 지원하는 구조.

## 초기 버전 기본 정책 제안

- 초대 가입, 개인 기록 기본 비공개. 루틴은 복사해서 공유하는 기능을 후속 개발.
- 한국 시간 기본값, 사용자별 시간대 설정 지원.
- 운동일지는 직접 입력만으로도 사용 가능. AI·Notion 장애가 기록 기능을 막지 않음.
- Notion은 최초 가져오기와 수동 재가져오기부터 제공. 양방향 동기화는 후속 범위.
- 종목별 마지막 세트 RIR 입력을 기본으로 제공하고, 필요하면 세트별 RIR 입력.
- 첫 버전은 온라인 사용. 일시적인 연결 끊김에 대비한 기기 내 초안 복구 제공.
- 식단, 웨어러블, 공개 피드, 순위, 트레이너 회원관리는 후속 범위.

## 기술 선택 제안

| 영역 | 기술 | 이유 |
|---|---|---|
| 앱·API | Next.js + TypeScript, Node.js LTS | 한 프로젝트에서 UI와 서버 관리, Docker standalone 배포 |
| UI | Tailwind CSS + shadcn/ui | 모바일 입력 화면과 접근성 구성 |
| DB | PostgreSQL | 사용자 권한 경계, 관계형 기록, 집계·동기화 이력 |
| ORM | Prisma | 스키마·마이그레이션 관리 |
| 검증 | Zod | 폼·API·AI 응답의 공통 검증 |
| 인증 | Better Auth 후보 | 초대 기반 이메일·비밀번호와 서버 세션; 구현 전 호환성 검증 |
| AI | 서버의 OpenAI SDK | 키를 서버에 보관하고 구조화된 초안 생성 |
| 연동 | Notion API, 후속 MCP SDK | 직접 가져오기와 ChatGPT 도구 호출 분리 |
| 배포 | Docker Compose + Portainer | 앱·DB의 설치 및 업데이트 단순화 |

정확한 패키지 버전은 구현 시작 시 호환성을 확인하고 잠금 파일에 고정합니다. Redis와 별도 워커는 초기 필수가 아닙니다. Notion 대량 가져오기는 DB 작업 이력과 체크포인트로 나누고, 재시작 복구와 실행 시간이 필요해지면 워커 컨테이너를 추가합니다.

## 실행 순서와 완료 기준

| 단계 | 작업 | 산출물·완료 기준 | 상태 |
|---|---|---|---|
| 1 | 요구·Notion 조사 | 현행 4개 DB와 운영 규칙 검토, 설계 초안 작성 | 완료 |
| 2 | 프로젝트·인증·DB 기반 | 가입 초대, 로그인, 마이그레이션; 다른 사용자 기록 접근 차단 검증 | 소스 작성, 설치·통합 검증 대기 |
| 3 | 종목·루틴·직접 운동 기록 | 종목별 가변 세트·중량·반복·RIR; 한 운동을 시작부터 종료까지 저장·재조회 | 예정 |
| 4 | 기록 조회·비교 | 지난 같은 종목 비교, 주간 기록, 실제 데이터만 통계 집계 | 예정 |
| 5 | 자연어·AI | 예시 문장의 구조화, 사용자 검토 후 저장, 중복 요청 및 비용 제한 검증 | 예정 |
| 6 | Notion 가져오기 | 소유자 지정·미리보기·중복 방지·수정 충돌 검토·중단 후 재개 검증 | 예정 |
| 7 | NAS 배포·운영 | amd64 이미지·Compose·설치 문서; NAS 재시작·백업 복구 검증 | 예정 |
| 8 | 실제 사용·MCP | 친구·동료 사용 피드백 반영; ChatGPT 연결 가능 범위를 확인한 후 최소 MCP 검증 | 예정 |

각 단계에서 구현 내용, 검증 결과, 남은 제약을 보고합니다. 설계 문서의 완료는 사용자 검토 완료나 실제 구현 완료를 뜻하지 않습니다.

## 검증 우선순위

- 사용자 A가 B의 세션·초안·Notion 연결·가져오기 작업을 읽거나 변경할 수 없는지.
- 세트마다 중량이 달라져도 계산이 맞는지, 누락 값과 실제 0을 구분하는지.
- 저장 재시도·동시 수정·재가져오기로 기록이 중복되거나 덮어써지지 않는지.
- 루틴·종목 수정이 과거 기록을 변경하지 않는지.
- 앱·NAS 재시작 후 데이터가 남고 백업으로 새 DB를 복구할 수 있는지.

## 구현과 별도로 확인할 운영 항목

외부 접속 도메인·HTTPS 방식, 기존 Portainer 설치 상태, 사용 중인 NAS 서비스, 초기 사용자 수, 개인별 AI 키 사용 여부는 아직 확인하지 않았습니다. 초기 설계는 관리자 소유 AI 키와 사용자별 사용량 제한을 가정합니다. 외부 공개 전 접속·인증 구성을 확정합니다.
