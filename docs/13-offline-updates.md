# B3 오프라인 안내·안전한 업데이트

작성일: 2026-10-28 (Asia/Seoul).

## 동작

- 운영 빌드에서만 `/sw.js`를 등록한다. worker는 Next BUILD_ID로 버전을 정하고 HTTP 캐시를 사용하지 않도록 제공한다. 생성된 public/sw.js는 Git에서 제외하며 빌드 때 재생성한다. 원본은 scripts/sw-template.js다.
- Cache Storage에는 공용 `/offline.html`만 저장한다. 개인 HTML·API·인증·초대·RSC·쓰기 요청·외부 요청은 저장하지 않는다. 공용 안내 문서는 쿠키 없이 가져온다.
- 같은 Origin의 GET 문서 탐색은 네트워크를 우선한다. 네트워크 오류일 때만 공용 안내를 보여준다. API/RSC는 이 fallback도 적용하지 않는다. HTTP 4xx/5xx를 성공 화면으로 바꾸지 않는다.
- 열린 앱에서 offline/online 이벤트를 안내하되 연결 복구를 저장 성공으로 표시하지 않는다. navigator.onLine은 서버 건강 상태를 보증하지 않는다. 새 문서 탐색이 실제로 실패하면 별도 오프라인 페이지로 안내한다.
- 오프라인 안내에는 개인 데이터·폼·토큰이 없고, 연결 후 사용자가 ‘다시 연결하기’를 눌러 돌아온다. 자동 쓰기 재시도·오프라인 일지 조회·저장은 제공하지 않는다.

## 업데이트 정책

- 새 worker는 설치 후 기다린다. install 시 skipWaiting하지 않는다. 첫 설치의 clients.claim도 페이지를 새로고침하지 않는다.
- 설정 화면에 한정하지 않고 앱 공통 안내에서 새 버전을 알린다. 브라우저 포커스 복귀 시에도 worker 업데이트를 확인한다.
- ‘업데이트 적용’을 누르면 현재 폼의 입력·자동 완성·초대 코드·선택 변경을 확인한다. 입력이 있으면 적용하지 않고 안내한다. 초대 코드는 주소에서 제거된 뒤 폼에 남아 있으므로 입력 보호 대상이다.
- 입력이 없으면 대기 worker에 활성화를 요청한다. 실제 controllerchange 시 입력 상태를 다시 검사하고 요청한 탭만 새로고침한다. 그 사이 입력이 생겼으면 새로고침하지 않는다.
- 다른 탭은 controllerchange가 발생해도 자동 새로고침하지 않는다. 각 탭이 자기 입력을 정리한 뒤 직접 적용한다. 이전 안내용 캐시는 새 worker 활성화 시 정리한다.
- 향후 폼 외 운동 초안은 `data-unsaved-changes="true"` 표시와 C7 초안 복구를 연결해야 한다. 현재 검증은 구현된 입력·선택 컨트롤 범위이며 모든 미래 편집기를 보호한다고 가정하지 않는다.
- 서버 배포 시 이전 JS 자원 유지와 API 하위 호환성은 별도로 필요하다. 열린 탭의 코드가 즉시 바뀌지 않으므로 worker 업데이트만으로 서버 호환성 문제가 해결되지는 않는다. E단계 배포 절차에 반영한다.

## 검증

```bash
cd /workspace/EasyWeightBaby
npm run build
npm run test:pwa
npm run test:production
npm run typecheck
```

- build와 타입 검사 통과. worker 문법, BUILD_ID 치환, standalone의 worker/오프라인 문서 포함, dotenv 제외를 확인했다.
- Chromium PWA 테스트 총 5개(상위 1+하위 4) pass, fail/skip 0. manifest·설치 조건·실제 프로토콜 설치·독립 실행·재실행의 기존 범위도 유지했다.
- 브라우저를 실제 offline 상태로 전환해 연결 끊김·복구 안내, API 네트워크 실패, 개인 정보 없는 문서 fallback, 재연결 후 인증된 홈 복귀를 확인했다. API 호출 후에도 캐시 키는 offline.html뿐이었다.
- 테스트용 역방향 프록시가 실제 worker 템플릿의 다음 버전을 제공해 waiting→안내→입력 보호→사용자 적용→새로고침을 확인했다. 프로젝트 worker 파일을 덮어쓰거나 내부 상태만 가짜로 변경한 검증이 아니다.
- 두 탭 모두 미입력 상태로 바꾸기 전에는 새로고침되지 않으며, 활성화 후 이전 안내 캐시가 삭제됨을 확인했다.
- 운영 회귀 테스트 총 3개 pass, fail/skip 0. DB 응답·브라우저 인증·정적 자원·설치 UI 분기를 확인했다.

이번 B3 테스트는 localhost 보안 컨텍스트 예외를 사용했다. B2의 로컬 신뢰 HTTPS 설치 결과와 구분한다. B3를 실제 HTTPS에서 반복하려면 12-pwa-installation.md의 인증서 신뢰·가상 디스플레이 준비와 scripts/test-pwa-https.py를 사용한다. NAS 도메인·실물 기기·완전 오프라인 동기화는 이번 검증에 포함되지 않는다.
