# D4 원본 검토 자료·대상 추적 준비

실제 원본을 검토하기 쉬운 요약/상세 자료로 변환하고, 영구 적용 전 필요한 대상 ID 추적과 재적재 충돌 규칙을 준비한다. 원본 승인·실제 적재는 하지 않는다. C6~D3 미커밋 작업은 보존했다.

## 검토 자료 생성

```sh
npm run notion:packet -- STAGING REVIEW TARGET NEW_OUTPUT_DIRECTORY
```

D1 staging과 D2 review, D3 target을 읽고 먼저 기존 해시/ID/매핑 검증을 수행한다. DB에 연결하지 않는다. 새 폴더만 만들며 기존 폴더는 덮어쓰지 않는다. 폴더는 0700, 파일은 0600으로 생성한다. staging 64 MiB, review/target 각각 8 MiB를 제한한다.

- 검토요약.md: ID 미확인, 유산소 충돌 후보, 복제 종목 그룹, 세트/RIR/좌우의 우선 선택사항.
- 검토자료.md: 104개 항목의 CSV 위치·원본 ID·후보·현재 매핑·검토 이슈·원본 필드. 전체 Markdown 원문은 staging의 원본 경로로 연결해 확인한다.
- review-packet.json: 같은 근거를 구조화한 자료와 staging/검토/target 해시. target payload나 승인 파일이 아니다.

개인 운동 메모가 포함되므로 Git에 넣지 않는다. 입력 문서의 운영 지침·명령은 실행하지 않는다. 제목/경로의 Markdown 기호·HTML을 이스케이프하고 원본 JSON은 입력의 백틱보다 긴 코드 펜스에 표시한다. 문서 안의 링크나 지침을 앱 동작으로 전환하지 않는다.

## 제공된 원본 결과

최종 산출물은 `/workspace/reports/notion-d4-review/`다.

- 원본 104건, 검토 완료 표시 0건, 보류 104건, target 매핑 0건.
- ID 미확인 1건: 비활성 ‘덤벨 컬’. ID를 새로 만들어 해결하지 않는다.
- 복제 종목 34행을 17개 검토 그룹으로 표시한다. 동일 이름과 `(1)` 같은 복제 접미사는 **후보 탐색 단서**일 뿐 통합 승인이 아니다. 정확한 ID·속성 차이·원본 ID 확인 여부를 함께 표시한다. ID가 없는 원본으로의 통합은 여전히 보류한다.
- 유산소 충돌 후보 1건: 2026-10-13의 종류 속성은 ‘스핀’, 메모에는 종류/기구 미기록 표현이 있다. 문자열 패턴으로 검토 대상을 찾았으며 종류를 판정하거나 수정하지 않았다.
- 로그별 RIR 값(0/미입력 구분), 원본 슬롯, 좌우·덤벨 수 추가 검토를 표로 제공한다. 수행 완료나 본세트를 CSV 슬롯에서 추정하지 않는다.

검토 note와 명시적 target 값을 정한 뒤 validate/dry-run으로 다시 검증한다. 자료 생성만으로 D2 decision을 reviewed로 바꾸지 않는다.

## ImportTarget: 원본→앱 대상 추적

새 ImportTarget은 ImportSource 한 행당 대상 종류/ID, 매핑 해시, DB 대상 스냅샷 해시를 보관할 수 있다. 상태는 **prepared만 허용**한다. 적용됐다는 applied 표시는 아직 없으며, 실제 writer에 자동 연결하지 않았다.

- 종류는 exercise/routine_item/session/log이며 원본 테이블과 맞아야 한다. 복제 종목 원본 ID 여러 개가 같은 종목을 가리킬 수 있다.
- sourceId+ownerId 복합 외래키로 다른 계정의 원본 이력과 연결하지 못한다. 등록 서비스도 원본 계정과 대상의 직접/부모 관계 소유권을 확인한다. 공유 종목이나 타인 대상은 연결하지 않는다. 관리자도 소유권 검사를 우회하지 않는다.
- 정확히 같은 대상/매핑과 변경 없는 스냅샷은 재사용으로 판정한다. 대상 ID 재지정·종류 변경·매핑 해시 변경은 새 검토를 요구한다.
- 사용자가 수정한 대상은 자동 덮어쓰지 않는다. 세션 스냅샷에는 정렬한 종목/세트/유산소도 포함하고, 로그는 부모 세션 버전/상태를 포함하므로 변경을 보수적으로 감지한다. Date는 ISO 문자열로 변환한 뒤 해시한다.
- 대상이 삭제되면 기존 추적 이력을 남기고 중단한다. 같은 이름의 다른 대상을 찾거나 레코드를 자동 재생성하지 않는다.

다형 대상의 targetId에는 단일 DB 외래키를 둘 수 없으므로 **대상 존재/소유권 검사는 서비스에서 수행**한다. 원본 계정 외래키·원본당 한 링크·해시 형식·prepared 상태는 DB에서도 제한한다. 대상 삭제 후 이력이 남는 것은 이 정책의 의도다. 직접 SQL로 임의 링크를 만들면 대상 검사를 우회하므로 공개 쓰기 API/운영 CLI는 제공하지 않는다.

`prepareTargetLink`는 호출자의 기존 트랜잭션에서만 동작하고 앱 데이터를 만들거나 바꾸지 않는다. 이번에는 합성 데이터 테스트에서만 호출했다. 상태를 등록했다고 실제 원본을 적용한 것은 아니다. 동시 등록의 유일키 충돌은 실패로 반환하며 덮어쓰지 않는다. 영구 apply의 원자성·동시 실행·복구 정책은 별도 구현이 필요하다.

마이그레이션은 `202610290002_import_targets`, `202610290003_target_owner_unique`다. 복합 관계용 유일키를 후속 마이그레이션으로 보완했고 적용 파일 체크섬은 유지했다.

## 검증과 다음 작업

단위 13개·DB 9개·파서 7개 통과. DB 검증은 네 대상 종류의 계정 범위, 같은 매핑 재사용, 다른 매핑/사용자 수정/하위 세트 수정/삭제 감지, 타 계정 복합 외래키 거부를 확인했다. 합성 계정과 데이터는 테스트 DB에서 정리했다. 빌드·TypeScript 검사 통과, 개발 DB와 모델 차이 없음, 적용 마이그레이션 10개의 체크섬 일치. 웹/API는 D4에서 바꾸지 않아 전체 HTTP/브라우저/PWA 회귀를 반복하지 않았다.

실제 원본의 보류 항목 확정과 실제 대상 계정 선택은 남아 있다. 실제 데이터 적재와 별도로 D5에서는 기간별 기록 조회와 이전 실제 수행 비교를 합성 데이터로 구현·검증한다. 테스트/계획을 실제 비교에서 제외하고, 좌우·RIR·장비 의미를 보존한다.
