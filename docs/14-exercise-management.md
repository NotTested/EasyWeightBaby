# C1 운동 종목 관리

작성일: 2026-10-28 (Asia/Seoul).

## 사용 흐름

루틴 화면의 ‘운동 종목 관리’에서 `/exercises`로 이동한다. 종목명·별칭을 검색하고, 새 종목을 등록하거나 목록의 편집을 눌러 수정한다. 모바일에서는 목록 상단 ‘종목 추가’로 편집 영역에 바로 이동할 수 있다.

- 이름, 별칭(쉼표 구분, 최대 12개), 도구, 부위, 수행 방식, 측정 방식, 벤치 각도, 메모, 활성 여부.
- 일반 회원은 본인 종목을 등록·수정·비활성화할 수 있다. 관리자는 공용 종목도 등록·수정할 수 있다.
- 공용 종목은 모두 조회할 수 있지만 관리자만 변경할 수 있다. 다른 회원의 개인 종목은 관리자에게도 보이지 않는다.
- 비활성화는 삭제가 아니다. ‘비활성 포함’에서 다시 활성화할 수 있다. 공개 범위·소유자는 편집으로 변경할 수 없다.
- 같은 이름은 공용 범위 또는 해당 개인 범위 안에서 중복 등록할 수 없다. 공용과 개인에 같은 이름이 존재할 수 있다. 별칭이 여러 종목과 겹치면 검색 결과에 모두 표시하며 자동으로 하나를 선택하지 않는다.
- 기본은 활성 종목 검색이며 정규화한 이름·별칭의 부분 문자열을 찾는다. 최대 100개를 반환하고 더 있으면 검색을 좁히도록 안내한다. 아직 페이지 이동·전체 일괄 편집은 없다.
- 기존 Notion 종목이나 예제 종목을 자동으로 넣지 않았다. 원본 ZIP 가져오기는 D단계다. 루틴 편집·운동 시작·세트 기록도 이번 범위가 아니다.

## 데이터·권한

Exercise 모델과 `202610280001_exercises` 마이그레이션을 추가했다. 기존 테이블·마이그레이션은 바꾸지 않았다.

- ownerId가 NULL이면 공용, 개인은 사용자 ID를 참조한다. scopeKey는 서버가 결정하며 DB CHECK로 소유자와 일치하도록 제한한다.
- 이름은 NFKC·앞뒤/중복 공백·소문자로 정규화해 scopeKey+nameKey 유일키로 중복을 막는다. 표시는 원래 입력을 보존한다.
- 별칭 배열과 검색용 정규화 텍스트를 저장한다. 쉼표는 UI 구분자이므로 개별 별칭에 포함할 수 없다.
- GET `/api/exercises`, GET `/api/exercises/:id`: 로그인 사용자 범위로 조회. 응답은 no-store다.
- POST `/api/exercises`, PATCH `/api/exercises/:id`: Origin·인증·Zod strict 입력·소유권·공용 쓰기 권한을 서버에서 확인한다. 클라이언트의 ownerId/scopeKey/역할 주입은 허용하지 않는다.
- PATCH는 전체 편집 필드와 version을 받는다. 동시 요청은 같은 버전에서 하나만 성공하며 나머지는 409다. 오류 시 폼을 지우거나 자동 덮어쓰지 않는다.
- API DELETE는 제공하지 않는다. 사용자 삭제 시 개인 종목은 DB 외래키 RESTRICT로 보호하며, 향후 계정 삭제 절차에서 별도로 다룬다.

## 화면·입력 보호

선택 항목과 메모는 접근성 이름을 명시해 기존 값이 라벨 이름에 섞이지 않도록 했다. 목록 로딩 중에는 오래된 행 편집을 막고, 선택을 바꿀 때 미저장 입력이 있으면 버릴지 확인한다.

종목 편집기는 변경·저장 중 data-unsaved-changes를 표시한다. 서버 확인이 끝난 편집 폼만 data-update-safe로 표시하여, 저장한 값이 남아 있어도 PWA 업데이트를 적용할 수 있게 한다. 변경·저장 요청 중에는 다시 안전 표시를 해제한다. 로그인·초대 같은 기존 폼은 이 예외를 적용하지 않는다. 페이지 이탈·브라우저 종료 후 초안 복구는 C7 범위이며 이번 작업에서 제공하지 않는다.

## 검증 및 재현

```bash
cd /workspace/EasyWeightBaby
npm run db:generate
npm run db:deploy
npm test
npm run test:integration
npm run test:browser
npm run build
npm run test:production
npm run test:pwa
```

모든 DB 테스트는 별도 _test DB를 사용한다. 테스트 생성 계정·개인/공용 종목만 정리하며 실제 기록을 삭제하거나 초기화하지 않는다.

- 정규화·중복 별칭·입력 범위·소유자 주입 거부 단위 테스트를 추가했다.
- HTTP 종목 검증은 공용/개인 생성·중복·검색·타인 접근(관리자 포함)·권한·공개 범위 변경 거부·동시 수정·비활성/복원을 확인한다.
- 브라우저는 1280/320px 개인 등록→별칭 검색→수정→비활성화→복원과 관리자 공용 등록·일반 회원 읽기 전용을 확인한다.
- PWA 검증은 미저장 종목 입력이 업데이트 중 남아 있고, 서버 저장 후에는 새로고침해도 종목이 다시 조회되는 흐름을 추가했다.
- 개발 DB의 migrate diff에서 Prisma 모델과 차이 없음을 확인했다.
- 최종 통과 결과: 단위 2개, HTTP 통합 13개, 브라우저 8개, 운영 3개, PWA 5개. fail/skip 0이며 운영 빌드의 TypeScript 검사도 통과했다. 브라우저 수에는 기존 인증 4개와 종목 관리 4개가 포함된다.

테스트 파일은 test-concurrency=1로 실행하고, 각 앱의 .next/dev 산출물을 정리한다. Origin과 인증 secret이 다른 테스트 앱의 개발 출력을 공유하지 않으며, 수동 next dev와 테스트도 동시에 실행하지 않는다. 운영 산출물·소스·.env는 이 정리에서 삭제하지 않는다.

반복 실행 중 로그인 회귀가 429를 받는 것을 응답 상태로 확인했다. 테스트 실행별 가상 클라이언트 IP를 분리했으며 앱의 속도 제한·DB 카운터를 비활성화하거나 전역 초기화하지 않았다. 브라우저 테스트는 로그인 API 응답도 명시적으로 확인한다. 로그인·가입 폼은 클라이언트 초기화 뒤 버튼을 활성화하고 기본 method를 POST로 지정해, 초기화 전 기본 GET 제출로 자격증명이 URL에 포함되지 않도록 보강했다.

다음 C2는 버전 있는 주간 루틴의 요일·순서·종목·목표 세트·반복 범위 편집이다. C1 종목을 재사용하며 운동 수행 기록 입력은 C3 이후로 남긴다.
